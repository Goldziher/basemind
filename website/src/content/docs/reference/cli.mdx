Every MCP tool has a CLI command that builds the same arguments and prints the same answer;
`tests/cli_parity/` enforces it. The CLI also keeps shorthands (`code callers`, `git recent`, ...) and
administrative commands with no MCP tool (`git churn`, `git by-path`, `code chunk`, `memory delete`,
`memory clear`, `cache`, `admin telemetry`), each declared CLI-only. Add `--json` to any tool
subcommand to print the tool's JSON.

| MCP tool | CLI command |
|---|---|
| `code_outline` | `code outline` |
| `code_symbols` | `code symbols` |
| `code_read` | `code read` (alias `expand`) |
| `code_grep` | `code grep` |
| `code_search` | `code search` (alias `semantic`) |
| `code_refs` | `code refs` (alias `references`); shorthands `callers`, `implementations`, `dependents`, `definition` |
| `find_files` | `code find`; `code files` lists |
| `docs_search` | `memory documents` |
| `git_log` | `git log`; shorthands `recent`, `touching`, `search`, `show`, `symbol-history` |
| `git_blame` | `git blame`; shorthand `blame-symbol` |
| `git_diff` | `git diff`; shorthands `status`, `diff-outline` |
| `memory_save` | `memory put` |
| `memory_search` | `memory search`, `memory get`, `memory list` |
| `index_status` | `status` (`admin repo` prints the same payload) |
| `index_rescan` | `rescan` |

Flags with a closed set of values (`--relation`, `--lane`, `--match`, `--window`) are validated by
clap: a typo fails with exit code 2 and the valid choices listed, and the
[completions](#other-commands) offer them.

Every list command takes the paging and budget flags its tool takes:

| Flag | Effect |
|---|---|
| `--limit <N>` | Maximum entries. |
| `--cursor <TOKEN>` | Resume from the previous page's `next_cursor`. |
| `--max-tokens <N>` | Token budget for the returned list (default 6000); the overflow is dropped and the response is flagged `budgeted`. |

`--format`, `--l2`, `--path-contains`, `--no-context`, `--line-start` / `--line-end`, `--field`,
`--body-chars`, `--hash-mode`, `--no-embed` and `--no-files` no longer exist; see
[Upgrading](/start/upgrading/).

| Group | Gate |
|---|---|
| `code`, `git`, `memory`, `admin` | always available |
| `agent`, `workspace` | `--features comms` |

Prebuilt downloads (Homebrew, npm, pip, GitHub releases) ship the build with `comms`.

## `code` — code lookups

```bash
basemind code outline <path> [--limit --cursor --max-tokens]
basemind code symbols <name> [--kind --path --language --fuzzy --limit --cursor --max-tokens]
basemind code read <path> [--symbol <name> [--kind] | --line <n> [--end-line <m>]]
basemind code grep <pattern> [--regex --path --language --context N --limit --cursor --max-tokens]
basemind code search <query> [--lane --path --language --limit --cursor --max-tokens]
basemind code refs <name> [--relation --path --line --column --match --limit --cursor --max-tokens]
basemind code callers <path> <name> [--limit --cursor --max-tokens]
basemind code implementations <name> [--limit --cursor --max-tokens]
basemind code dependents <module> [--limit --cursor]
basemind code definition <path> <line> <name> [--column]
basemind code find [query] [--path --language --limit --cursor --max-tokens]
basemind code files [--path --language --limit --cursor --max-tokens]
basemind code chunk <path> [--chunk-id --byte-start]
basemind code impact (<path|symbol> | --symbol <name> | --diff <rev|A..B> | --changed) [--depth --include-type-imports --include-module-decls]
basemind code cycles [--path --max-size | --check <from> <to>] [--include-type-imports --include-module-decls]
basemind code explain <symbol|path|path:line> [--sections --limit --depth --no-code --max-tokens]
basemind code deadcode [--path --kind files|symbols|imports --tier high|medium|low --limit --fail-on-dead-code]
basemind code migration check [name] [--fail-on-remaining --ranges]
```

| Command | Purpose |
|---|---|
| `outline <path>` | A file's structure: symbols with kind, signature and 1-based lines, plus imports. Read this instead of the file. Code files only; documents are searched with `memory documents`. |
| `symbols <name> [--kind --path --language --fuzzy]` | Find a definition by name across every indexed file. Ranked: exact, prefix, substring, then (with `--fuzzy`) fuzzy subsequence. |
| `read <path> --symbol <name> [--kind]` / `read <path> --line <n> [--end-line <m>]` | One symbol's source body, or a 1-based inclusive line span. Alias `expand`. |
| `grep <pattern> [--regex --path --language --context N]` | Text search over the indexed code. The pattern is literal unless `--regex`. `--path` is a repo-relative prefix, or a glob when it holds `*`. `--context N` (0-10) adds the N lines before and after each hit. |
| `search <query> [--lane hybrid\|semantic\|keyword --path --language]` | Search code by meaning; returns pointers, read a hit with `code read`. Alias `semantic`. Needs `--features code-search`. |
| `refs <name> [--relation callers\|implementations\|importers\|definition --path --line --column --match exact\|substring]` | Usages of a name. Without `--path`, every call site of the exact identifier; with `--path`, callers of the definition in that file. Alias `references`. |
| `callers <path> <name>` | Shorthand for `refs <name> --path <path>`. |
| `implementations <name>` | Shorthand for `refs <name> --relation implementations`. |
| `dependents <module>` | Shorthand for `refs <module> --relation importers`. |
| `definition <path> <line> <name> [--column]` | Shorthand for `refs <name> --relation definition --path <path> --line <line>`: the definition the reference binds to. |
| `find [query] [--path --language]` | Fuzzy file-name or path search, ranked by score; a listing when the query is omitted. Covers documents as well as code. |
| `files [--path --language]` | List indexed files, code and documents alike. |
| `chunk <path> [--chunk-id --byte-start]` | Fetch one code-search chunk body. CLI only. Needs `--features code-search`. |
| `impact <path\|symbol> [--depth]` / `impact --diff <rev\|A..B>` / `impact --changed` | Files that import a file, a symbol's defining files or a change's files, transitively through the file-level import graph, each with its depth and whether it is in a cycle. CLI only. |
| `cycles [--path --max-size]` / `cycles --check <from> <to>` | Import cycles, smallest first, each with an import chain that closes it; or whether `from` importing `to` would close one. Type-only imports and Rust `mod` declarations count only with `--include-type-imports` / `--include-module-decls`. CLI only. |
| `explain <symbol\|path\|path:line> [--sections --limit --depth --no-code --max-tokens]` | One briefing: a symbol's definition, short body, graded callers, callees, importers and history, or a file's outline, imports, importers, calls in and out by file, hotspot signals, recent commits and owners; each cut section names the call that continues it. CLI only. |
| `deadcode [--path --kind --tier --limit --fail-on-dead-code]` | Files no entry point reaches through the import graph, definitions whose name nothing else spells and imports that resolve to nothing, each with a confidence tier and its reason, plus a coverage note per language. `--fail-on-dead-code` exits 1 on a `high` finding (or one at `--tier`) and on a report that judged nothing. Extra entry points come from `[analysis] entry_points`. CLI only. |
| `migration check [name] [--fail-on-remaining --ranges]` | Remaining uses of the old forms named in `.basemind/migrations/<name>.toml`, per rule and file, with the share migrated and the progress across runs. `--fail-on-remaining` exits 1. CLI only. |

## `git` — git history

Requires running inside a git repository.

```bash
basemind git log [--path --query --author --symbol --rev --limit --cursor --max-tokens]
basemind git blame <path> [--line --end-line --symbol --rev --limit --cursor]
basemind git diff [path] [--from --to --structural]
basemind git status
basemind git recent [--limit --cursor --max-tokens]
basemind git touching <path> [--limit --cursor --max-tokens]
basemind git search <query> [--author --limit --cursor --max-tokens]
basemind git show <rev>
basemind git symbol-history <path> <name> [--limit --cursor]
basemind git blame-symbol <path> <name> [--rev --limit --cursor]
basemind git diff-outline <path> [--rev]
basemind git churn [--window --top-k]
basemind git by-path <pattern> [--window --limit --cursor --max-tokens]
basemind git hotspots [--since 90d --path --limit]
```

| Command | Purpose |
|---|---|
| `log [--path --query --author --symbol --rev]` | No flags: recent commits. `--path`: commits touching a file, or a directory when it ends with `/`. `--query` / `--author`: full-text search. `--path` with `--symbol`: when that symbol's body changed. `--rev`: that one commit in full. |
| `blame <path> [--line --end-line --symbol --rev]` | Who last changed a file, a 1-based line span, or one symbol. |
| `diff [path] [--from --to --structural]` | No arguments: working-tree status. A path alone: that file's working-tree diff against HEAD. `--from` / `--to`: diff between revisions. `--structural`: symbols added and removed instead of text hunks. |
| `status` | Shorthand for `diff` with no arguments. |
| `recent` | Shorthand for `log` with no filter. |
| `touching <path>` | Shorthand for `log --path <path>`. |
| `search <query> [--author]` | Shorthand for `log --query <query>`. |
| `show <rev>` | Shorthand for `log --rev <rev>`. |
| `symbol-history <path> <name>` | Shorthand for `log --path <path> --symbol <name>`. |
| `blame-symbol <path> <name> [--rev]` | Shorthand for `blame <path> --symbol <name>`. |
| `diff-outline <path> [--rev]` | Shorthand for `diff <path> --structural --from <rev>`. |
| `churn [--window --top-k]` | Top files by commit count over a recent window. CLI only. |
| `by-path <pattern> [--window]` | Commits whose changed paths match a regex. CLI only. |
| `hotspots [--since --path --limit]` | Files with two or more of commits, authors, lines, symbols, longest function and importers in the top 10% of the files changed in the window (`--since` `<N>d`, `<N>w` or `<N>y`, default `90d`; `--limit` default 20, at most 200). Raw numbers, no score. CLI only. |

## `memory` — shared memory and documents

```bash
basemind memory put <key> <value> [--tag <t>]... [--individual]
basemind memory search <query> [--limit --individual] [--tag <t>]...
basemind memory get <key> [--individual]
basemind memory list [--prefix --limit --individual --cursor] [--tag <t>]...
basemind memory delete <key> [--individual]
basemind memory clear [--yes]
basemind memory documents <query> [--mime-type --keywords --entity --format --path --limit --cursor --max-tokens]
```

| Command | Purpose |
|---|---|
| `put <key> <value> [--tag --individual]` | Write a durable note (`memory_save`). `--individual` uses the per-agent tier instead of shared (group). |
| `search <query> [--limit --tag --individual]` | Search stored notes by meaning; `--tag` (repeatable) keeps notes carrying any of them. |
| `get <key> [--individual]` | Read one note by key. |
| `list [--prefix --tag --limit --individual]` | List notes, optionally by key prefix or tags (any of them). |
| `delete <key> [--individual]` | Remove a note by key. CLI only. |
| `clear [--yes]` | Remove every note of this repository and their vectors. Needs `--yes` off a terminal. CLI only. |
| `documents <query> [--mime-type --keywords --entity --format --path]` | Semantic search over indexed documents (`docs_search`) instead of opening them. |

## `admin` — administration

```bash
basemind admin repo
basemind admin telemetry [--window today|1h|24h|all] [--tool]
basemind admin tokens --stdin
basemind admin eval --tasks <FILE> [--out --report --markdown --baseline --tolerance --cost-tolerance --min-recall --warmup --mode]
```

`status`, `rescan` and `cache stats|gc|clear` live at the top level
(see [Other commands](#other-commands)).

| Command | Purpose |
|---|---|
| `repo` | The same payload as `status`: index health plus repository branch and HEAD sha. |
| `telemetry [--window --tool]` | Aggregate recorded tool calls into a usage and token-savings summary. CLI only. |
| `tokens --stdin` | Count tokens in stdin with the o200k tokenizer and print just the integer (needs the `tokenizer` feature, which `documents` includes). CLI-only; no `--json` envelope. |
| `eval --tasks <FILE> [...]` | Score retrieval quality, latency and token savings over a JSONL task file. CLI-only; see [Evaluation](/reference/evaluation/). |

## `agent` — multi-agent coordination

Requires `--features comms`. The three commands mirror the MCP tools `agent_post`, `agent_inbox`
and `agent_threads` flag for field; `--json` prints the tool's response. Every command takes
`--as <name>` to act as the sub-identity `<principal>.<name>` instead of the checkout's principal
(used for orchestrating several subagents).

```bash
basemind agent post --body <text> (--subject <s> [--to <id>...] [--paths <p>...] | --thread <t> | --reply-to <id>) [--as]
basemind agent inbox [--thread --id --unread <bool> --peek --announce --wait-secs --limit --cursor --as]
basemind agent threads [--query --path --thread --join --leave --invite <id>... --archive --archived --limit --cursor --as]
basemind agent status
basemind agent cleanup [--archive <thread>...]
basemind agent hook pre-tool-use
basemind agent hook name
```

| Command | Purpose |
|---|---|
| `post` | Send a message. `--subject` starts a thread (`--to` makes it invitation-only, `--paths` scopes it); `--thread` or `--reply-to` continues one. |
| `inbox` | Read unread messages, bodies inline; reading marks read. `--peek` does not, `--unread false` reads history, `--id` reads one message whole, `--wait-secs` (0 to 40) waits. `--announce` lists front matter only and never marks read (CLI and hooks only). |
| `threads` | List threads (`--query`, `--path`), describe one (`--thread`), or change it with `--join`, `--leave`, `--invite`, `--archive`. |
| `status` | Who this checkout acts as (principal, where the id came from, host, root) and the daemon's agent store: directory, state (open, newer, unreadable), version, posts, live serve sessions of this principal, repository. |
| `cleanup [--archive <thread>...]` | Operator: archive each named thread, whoever created it, then run one retention sweep. |
| `hook pre-tool-use` / `hook name` | Read a hook event JSON on stdin: the first answers a `PreToolUse` event for an agent tool with the `as` to inject, the second prints the session's name. For the plugin hooks. |

## `workspace` — machine-wide repo/worktree registry

Requires `--features comms`. Read-only listings of the daemon's registry; they have no MCP tool.

```bash
basemind workspace workspaces
basemind workspace worktrees <repo-id>
basemind workspace branches <repo-id>
```

| Command | Purpose |
|---|---|
| `workspaces` | Every repository the machine daemon has indexed. |
| `worktrees <repo-id>` | Git worktrees of a registered repo, with their branches. |
| `branches <repo-id>` | Branches known to a registered repo. |

## `comms` — broker daemon lifecycle

Requires `--features comms`. This is the daemon lifecycle only; messaging lives under
`basemind agent` (above). `basemind agents` is gone: its verbs map to `agent post|inbox|threads`.

```bash
basemind comms daemon
basemind comms start
basemind comms stop [--all]
basemind comms status
basemind comms doctor [--probe --clear-fatal]
basemind comms cleanup [--dry-run --older-than <days>]
```

| Command | Purpose |
|---|---|
| `daemon` | Run the broker loop in the foreground: bind the singleton socket, serve front-ends, block until shutdown. |
| `start` | Ensure the daemon is running (spawn if needed); no-op when already alive. |
| `stop [--all]` | Ask the running daemon to drain and stop. `--all` stops every live daemon of this version's protocol generation on this machine, not just the current one; a 0.33 daemon is stopped with the 0.33 binary. |
| `status` | Report the daemon's pid / version / uptime / room + subscriber counts. |
| `doctor [--probe --clear-fatal]` | List every live daemon of this version's protocol generation on this machine (pid / comms dir / version / uptime), flag a pile-up over the ceiling, and prune dead registry entries. Reports process liveness only unless `--probe` is given, which also asks each daemon whether it can serve. `--clear-fatal` acknowledges and deletes the recorded fatal store error for this comms dir. |
| `cleanup [--dry-run --older-than <days>]` | Remove rendezvous files no daemon uses: other protocol generations' directories and the files releases up to 0.33 left in the comms directory, when this command can take their `daemon.lock` and nothing in them changed for 30 days. `--older-than 0` drops the age test, so another release's message store goes as soon as none of its daemons runs. An entry without a `daemon.lock` is skipped. Never touches this version's generation and contacts no daemon. |

## Other commands

```bash
basemind scan [--staged | --rev <REV>] [--no-git-history --rebuild-git-history] [--documents-*]
basemind rescan [PATH...] [--no-git-history --rebuild-git-history]
basemind watch
basemind serve
basemind status
basemind overview [--sections a,b --limit N]
basemind sessions [--since YYYY-MM-DD]
basemind doctor
basemind completions <bash|zsh|fish|elvish|powershell>
basemind man
basemind manual [topic]
basemind init [--yes --with --without --rules-target --settings-target --config-dir .config|.config/basemind --no-rules --no-usage-rules --no-setup-notes --print]
basemind lang list|install|clean
basemind hook install [--force]
basemind cache stats
basemind cache gc [--dry-run]
basemind cache clear [--component]
basemind daemon ensure
basemind statusline
```

| Command | Purpose |
|---|---|
| `scan [--staged \| --rev <REV>] [--no-git-history --rebuild-git-history]` | Full index of the project. `--staged` indexes the git index instead of the working tree; `--rev` indexes a revision into a separate `rev-<sha7>` view. The `--documents-*` flags override the matching `[documents]` keys for this run (each also has a `BASEMIND_DOCUMENTS_*` env var). The `--llm-*` flags and `BASEMIND_LLM_*` variables are deprecated: still accepted, and ignored. Ctrl-C stops the scan cleanly. |
| `rescan [PATH...] [--no-git-history --rebuild-git-history]` | Update one or more paths incrementally, or the whole tree when no path is given. When the daemon is running the rescan is forwarded to it (the daemon is the sole index writer); otherwise it runs in-process under the workspace writer lock. Ctrl-C stops it cleanly. The summary (also when forwarded to the daemon) reports `docs_degraded` and `doc_timeouts` when non-zero. |
| `watch` | Long-running watcher; keeps the code map current as files change (no server). |
| `serve` | Ensure the daemon is up and relay this process's stdio to it as the MCP server. The daemon keeps the index fresh. |
| `status` | Index health and repo identity for this workspace (`index_status`): file counts per language, scan state, cache directory, branch and HEAD. |
| `overview [--sections --limit]` | The repository's shape in one call: languages with file and line counts, top-level directories, build manifests and the entry points they declare, the largest and most-imported files, HTTP routes, naming conventions per language, the latest commits. CLI only; answered by the daemon when one runs. |
| `sessions [--since YYYY-MM-DD]` | Per session of the local Claude Code and Codex transcripts of this repository and its worktrees, subagents under their parent: basemind calls against shell searches and whole-file reads. Counts and paths only; a removed worktree's sessions are not counted. CLI only. |
| `doctor` | Check root, config, index, grammars, pre-commit hook and daemon; exits 1 when a check fails. |
| `completions <shell>` | Print a shell completion script to stdout. |
| `man` | Print the man page (roff) to stdout. |
| `manual [topic]` | Print the offline manual: an index, or one topic (`code`, `resolution`, `git`, `documents`, `memory`, `agents`, `indexing`, `paging`, `setup`, `exit-codes`, `environment`, `troubleshooting`). Needs no index. |
| `init [--yes --with --without --rules-target --settings-target --config-dir --no-rules --no-usage-rules --no-setup-notes --print]` | Re-runnable onboarding: write `basemind.toml`, select capabilities, inject usage rules into a gitignored local rules file by default, optionally auto-approve basemind's tools in Claude Code settings. See [Get started](/start/installation/#get-started). |
| `lang list\|install\|clean` | Manage downloaded tree-sitter grammars. `install` also fetches every grammar marked `preload = true` under `[languages.<name>]`. |
| `hook install [--force]` | Add a git pre-commit hook that runs `basemind scan --staged`. Honours `core.hooksPath`, works in linked worktrees, never blocks a commit, and refuses to replace a hook basemind did not write unless `--force` (the old one is kept as `pre-commit.bak`, or `pre-commit.bak.1`, `.bak.2`, … when earlier backups exist). |
| `cache stats`, `cache gc [--dry-run]`, `cache clear [--component --yes]` | Offline path directly against the machine-global cache. `gc` runs the real cross-workspace reference-counted sweep (blobs younger than six hours are kept; `BASEMIND_BLOB_GC_GRACE_SECS` overrides) and prints what it removed. The `cache` commands have no MCP tool. `gc --dry-run` only counts blobs and deletes nothing. `--component` is `blobs`, `views`, `lance`, `git-cache` (default), `telemetry`, `all`, or `views:<name>` for one view. Everything except `git-cache` is destructive: it prompts on a terminal and requires `--yes` otherwise (exit 2). `clear` exits 3 while a writer holds the workspace lock, and for `blobs` while the daemon runs; `blobs` is the machine-global extraction store shared by every workspace. |
| `daemon ensure` | Ensure the daemon's streamable-HTTP MCP transport is up; idempotent. Needs `--features comms`. |
| `statusline` | Print a one-line summary of the daemon's hot workspaces, for a shell statusline. Silent and exits 0 when no daemon is running. |

## Output, exit codes and the daemon

Human output is a generic table or key/value view. Table cells and outline signatures wider than 200
characters are cut with an ellipsis (key/value fields never are), and the number of cut cells is
reported on stderr; `--json` always carries the full values. The timing footer (startup time plus the
tool's own latency) and other diagnostics go to **stderr**, so stdout stays pipeable.

| Exit code | Meaning |
|---|---|
| `0` | Success. |
| `1` | Runtime error (I/O, scan failure, a tool reported an error, a failed `doctor` check). |
| `2` | Usage error: a bad flag or value (clap), a path outside the repo, or a destructive command without `--yes`. |
| `3` | Busy: another process holds the workspace writer lock. Retry later, or start the daemon so the call is forwarded. |
| `4` | Unavailable: the operation needs the comms daemon and none is reachable. |
| `130` | Interrupted (Ctrl-C). Work committed before the interrupt is kept; a second Ctrl-C aborts immediately. |

When the comms daemon is running it is the sole index writer, so the one-shot tool subcommands open
the store without the index and forward index-dependent work to the daemon: `memory`, `code
refs`, the `code grep` trigram prefilter, and `rescan`. Without a daemon they read
the index directly and read-only.

<Aside type="note">
Global flags (`--root`, `--quiet`, `--verbose`, `--no-color`, `--json`, `--view`) apply across all
subcommands, though `--json` only takes effect on the tool subcommands (`code`, `git`,
`memory`, `admin`, `status`, `overview`, `cache`, `doctor`, and — with `--features comms` — `comms`, `agent`,
`workspace`, `daemon`); `--view` also applies to `serve`. Ignored flags log a warning. Cursor-based pagination
(`--cursor`) is covered in the paging table above.
</Aside>
