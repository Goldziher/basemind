basemind pre-indexes your codebase using tree-sitter, mapping symbols, calls, and imports
across 300+ languages. Structural queries resolve in milliseconds (an outline in about a
millisecond, symbol and reference lookups in single-digit milliseconds on a 74k-file monorepo;
see [Performance](/reference/performance/)) and return **paths, line
numbers, and signatures — not file bodies** — so they cost a fraction of the tokens of
reading source.

## Precise, scope- and import-aware resolution

Navigation is **scope- and import-aware** for JavaScript/TypeScript (via oxc) and for
**Python and Java** — via an in-tree, tree-sitter-0.26 fork of GitHub's stack-graphs engines
(vendored under `crates/`) executing `.tsg` name-binding rules, with no per-language LSP
server. Every other language still gets fast tree-sitter scope binding.

This resolves each use to the definition it actually binds to: a shadowed local isn't
confused with an import, and `code_refs` with `relation: "definition"` lands on the right target — including across
files, for Python dotted/relative imports and for JS/TS module resolution (Node resolution
plus tsconfig `paths` aliases via `oxc_resolver`).

<Aside type="note">
Resolution **refines but never shrinks** a result set. `code_refs` with a `path` reports every call
site whose callee matches the name, the same sound floor a call without `path` uses, and marks each
hit `resolved` when resolution proved the binding (`resolved_total` counts them). It does
**not** filter down to only the resolved subset: resolution can't see through a module-object
import (`from pkg import mod` then `mod.f()`) or an unresolvable alias, so filtering would drop
real callers. Filter on `resolved` for precision; trust `total` for completeness.
</Aside>

Known limitation this release: Java cross-file resolution of a **member call** on an imported
type (`Foo.greet()`) is not yet resolved — the imported type itself resolves, the method call
on it does not.

Toggle with `[code_intel] precise_resolution` in `basemind.toml` (default `true`). Set it to
`false` to fall back to tree-sitter locals binding for every language.

## Core tools

Each job is its own MCP tool with an exact schema; the CLI commands are under `basemind code`.
Every line and column is 1-based. See the [MCP tools reference](/reference/mcp-tools/) for all
arguments.

### `code_outline`

Get a file's structure: every symbol with its kind, signature and 1-based `line` / `end_line`, plus
the file's imports.

```json
{
  "path": "src/store.rs"
}
```

Returns a table of contents you can scan in seconds instead of reading a thousand-line file.
Feed a span to `code_read`. Code files only.

### `code_symbols`

Find where a symbol is defined, by name, across all indexed files. Results are ranked: exact name,
then prefix, then substring, then (with `fuzzy: true`) fuzzy subsequence. Matching is
case-sensitive. Optionally filter by `kind` (function, method, struct, enum, class, interface,
trait, type, const, module, macro).

```json
{
  "name": "parse_config",
  "kind": "function"
}
```

Returns path, line and signature for each match.

### `code_read`

Read one symbol's source body, or an exact line span, instead of the whole file. Pass `symbol`, or
`line` with `end_line`; not both. Bodies over 128 KiB are cut and flagged `truncated`, with
`omitted_bytes` saying how much was left out.

```json
{
  "path": "src/store.rs",
  "symbol": "open"
}
```

```json
{
  "path": "src/store.rs",
  "line": 120,
  "end_line": 160
}
```

### `code_refs`

One tool answers "what calls X", "what implements X", "what imports X" and "which definition does
this reference bind to". `relation` picks the question (default `callers`).

Call sites of a name. The identifier is matched exactly, with no scope resolution: `Foo::bar()` and
`bar()` both match `name: "bar"`, and `bar_baz()` does not. Pass `match: "substring"` to match
longer names too.

```json
{
  "name": "open_store"
}
```

Callers of one definition. `path` pins the definition in that file. A hit then has `resolved: true`
when resolution proved the binding, `resolved: false` when it checked and could not, and no
`resolved` when the hit was not checked; `resolution` says why when nothing could be checked. A
pinned file edited since it was indexed is an error naming `index_rescan`.

```json
{
  "name": "open_store",
  "path": "src/store.rs"
}
```

Types that implement or inherit from a name: Rust `impl` blocks, Python `class` inheritance,
TypeScript/JavaScript class declarations.

```json
{
  "name": "Drawable",
  "relation": "implementations"
}
```

Files importing a module (a heuristic reverse lookup over import statements).

```json
{
  "name": "tokio::sync",
  "relation": "importers"
}
```

Go-to-definition: resolve the reference `name` at `path`:`line` to the definition it binds to.
`column` (1-based) is optional and defaults to where `name` occurs on the line. Intra-file
resolution uses tree-sitter `locals` across 80+ languages; JavaScript/TypeScript, Python and Java
additionally get precise, scope- and import-aware resolution, including cross-file. See
[Precise, scope- and import-aware resolution](#precise-scope--and-import-aware-resolution) above.

```json
{
  "name": "open_store",
  "relation": "definition",
  "path": "src/main.rs",
  "line": 42
}
```

Call-site lookups are backed by an indexed call-site table and capped by `limit` (default 100).
A session the daemon serves (the standard deployment) reads the daemon's index, so `total` and
cursors are complete and identical to what a writer session sees. A session that holds no index (a
CLI command or a second `serve` beside a writer, with no daemon) refuses call sites, callers and
implementations as busy, naming `basemind comms start`.

### `code_grep`

Text search over the contents of indexed code files. `pattern` is literal text unless `regex: true`
(Rust `regex` syntax). `path` is a repo-relative prefix, or a glob when it holds `*`. Each
hit has the path, line, the full line `text` and the enclosing `symbol` (`name`, `kind`);
`context: N` (0-10) adds the N lines before and after each hit, overlapping windows written once.

```json
{
  "pattern": "cache_root(",
  "path": "src/"
}
```

```json
{
  "pattern": "fn \\w+_call",
  "regex": true
}
```

The scanner keeps a small per-file trigram bloom filter (about 12.8 % of the indexed code
bytes). A grep skips every file whose filter proves it cannot contain a literal the pattern
requires, so on a 74k-file monorepo the 15 benchmark patterns dropped from several seconds to
about 130 ms p50 with identical results (ADR-0012). A file is skipped only when its size and
mtime still match the scan, so edited, added or deleted files are still searched. Regex patterns
with no required 3-byte literal (`.*`, `(?i)k`) sweep every file. Set `BASEMIND_GREP_BLOOM=0` to
force the full sweep. An existing index gains its filters on the next scan; no wipe is needed.

`code_grep` also finds exact text in markdown, config and data files (Markdown, JSON, YAML, TOML,
...). They live in the document tier, so search them by meaning with `docs_search`.

### `find_files`

Locate a file by a fuzzy fragment of its name or path, or list indexed files when `query` is
omitted. Filter by `language` or `path` (a prefix, or a glob when it holds `*`). Covers code and documents (markdown, config, PDFs).

```json
{
  "query": "readme"
}
```

### `index_status`

Index health and repo identity: file counts per language, scan and degraded state, the cache
directory, and the repository's branch and HEAD. Call it when a result is unexpectedly empty or
says "not indexed".

## Discipline

- **`code_outline` a file before you open it.** A 1000-line file becomes a 30-line table of
  contents. Then `code_read` only the symbol or span you need.
- **`code_symbols` instead of grep for a definition.** Returns indexed symbol names and
  positions, skipping comment/string noise.
- **`code_refs` instead of grepping call sites.** Indexed call edges, not text matches.
- **`code_grep` instead of shelling out to ripgrep.** It searches the indexed code files and
  returns capped, structured hits with the enclosing symbol.
- **Do not re-read a file basemind already mapped.** If the outline answered the question,
  stop.
- **The index follows your edits**: no rescan and no server reconnect after each one. If a
  result says `stale` or a new file is missing, run `index_rescan {"paths":[...]}` for the files
  you touched; run `index_rescan {}` only when `index_status` reports an empty or degraded index.

<Aside type="note">
Lists are capped by `limit` (default 100 for `code_symbols` / `code_grep` / `code_refs`, 500 for
`code_outline`, 200 for `find_files`) and trimmed to `max_tokens` (default 6000); a trimmed
response sets `budgeted` and returns `next_cursor`. Index scanners use `scan_cap = limit * 8` (at
least 2000) to bound work on common names.
</Aside>
