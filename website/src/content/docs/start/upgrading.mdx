An upgrade never asks you to wipe the cache. basemind keeps its index in a machine-global cache
(`BASEMIND_DATA_HOME`, default `~/.local/share/basemind`): per-workspace views, LanceDB tables and git
history under `cache/workspaces/<key>/`, and one content-addressed blob store under `cache/blobs/`
shared by every workspace. The next scan migrates what changed and cleans up what it displaced.

## Upgrading to the verb tools (ADR-0018)

The mode-dispatched MCP tools `code`, `git`, `memory` and `admin` are replaced by one tool per job.
This is a breaking change with no aliases: a call to an old tool name fails. No tool below takes a
`mode` argument. `agents` and `workspace` are unchanged. The plugin's skills, commands, hooks and
rules ship in the same release, and the plugin downloads the version-matched binary; update any MCP
calls, permission allow-lists and scripts of your own. The tools are always loaded
(`_meta["anthropic/alwaysLoad"]: true`), so an agent calls them directly, with no tool-search round
trip. See the [MCP tools reference](/reference/mcp-tools/) for every argument.

### Removed arguments

- `mode`, on every tool above.
- `format` (`"toon"`): responses are JSON.
- Hidden aliases such as `q`, `needle` and `token_budget`: only the documented names are accepted.
- `field` on commit search: pass `query` for messages, `author` for authors.

### CLI changes

The command groups keep their names, and the old subcommands stay as shorthands (`code callers`,
`git recent`, `git blame-symbol`, ...). New commands mirror the tools: `code read` (alias `expand`),
`code search` (alias `semantic`), `code refs` (alias `references`), `git log`, and `git diff` with
`--from` / `--to` / `--structural`. See the [CLI reference](/reference/cli/).

| Old | New |
|---|---|
| `code expand <path> <name>` | `code read <path> --symbol <name>` |
| `code grep --path-contains <p>` | `code grep --path <p>` |
| `code grep <regex>` | `code grep <regex> --regex` (the pattern is literal by default) |
| `code grep --no-context` | default; `--context` adds the surrounding lines |
| `code files --path-contains <p>` | `code files --path-prefix <p>` |
| `code definition <path> <line>` | `code definition <path> <line> <name>` |
| `git blame --line-start <n> --line-end <m>` | `git blame --line <n> --end-line <m>` |
| `git diff <path> <old> <new>` | `git diff <path> --from <old> --to <new>` |
| `git search --field author <x>` | `git log --author <x>` |
| `--format json\|toon` | removed; the global `--json` prints the tool's JSON |
| `--l2`, `--body-chars`, `--hash-mode`, `--no-embed`, `--no-files` | removed |

### Behaviour changes

- **`code_grep` is literal by default.** A pattern that relied on regex syntax needs `regex: true`
  (`--regex`). `path` is a substring of the repo-relative path; a glob is rejected.
- **Lines are 1-based everywhere**: `line`, `end_line` and `column`, in arguments and results.
  Outline, symbol and caller rows used to be 0-based.
- **`code_refs` matches the exact identifier.** `name: "open"` no longer counts call sites of
  `open_store`. Pass `match: "substring"` for the old behaviour.
- **Unknown arguments are rejected** with a did-you-mean suggestion and the accepted list. They used
  to be dropped silently, so a misspelled filter ran unscoped and reported success.
- **Errors are tool results.** A failure the caller can fix comes back with `isError: true` and text
  naming the fix, not as a JSON-RPC error.
- **Default token budget.** Every list is trimmed to 6000 tokens unless `max_tokens` says otherwise;
  a trimmed response sets `budgeted` and returns `next_cursor`.
- **`git_diff` reads the working tree.** No arguments returns the status; `path` alone diffs that
  file against HEAD.
- **`find_files` covers documents** (markdown, config, PDFs) as well as code.
- **`index_status.cache_dir`** is basemind's cache directory. It used to report the tree-sitter
  grammar directory.
- **Results are inline.** A server-side Task is returned only for a call still running after 3 s
  (`index_rescan`, `code_search`, `docs_search`). Fast calls used to come back as background tasks.
- **An empty index is reported**, never returned as a plain empty result: the response carries a
  `notice` with `state: "empty_index"`.
- **Telemetry keys are the tool names.**

## Upgrading from 0.28 to 0.29

0.29 bumps the release minor, so the first scan rebuilds the index, and it reshapes the CLI.

1. Stop the old daemon before the first scan: `basemind comms stop` (add `--all` to stop every daemon
   on the machine). Otherwise the previous binary's daemon keeps running with the old schema and
   still owns the index.
2. Run `basemind scan`. Each view's `index.msgpack` and Fjall index are reset on open and every file is
   re-extracted, overwriting stale blobs in place; the git cache refills lazily. The LanceDB document
   tables and the blob store are not wiped, and the scan's cleanup pass reclaims orphaned blobs.
   Expect a full-scan duration once.
3. Re-run `basemind hook install`. The new hook honours `core.hooksPath` and linked worktrees, fails
   open, and it will not overwrite a pre-commit hook it did not write unless you pass `--force` (the
   old one is kept as `pre-commit.bak`).
4. Update scripts for the renamed commands. No aliases remain:

| 0.28 | 0.29 |
|---|---|
| `admin status` | `status` |
| `admin rescan` | `rescan` |
| `admin cache-stats` | `cache stats` |
| `admin gc` | `cache gc` (deletes; `--dry-run` reports) |
| `admin cache-clear` | `cache clear` (needs `--yes` outside a terminal) |
| `serve --git-cache-mem`, `--no-git-cache-disk`, `--no-watch`, `--documents-*` | removed (`serve` takes no flags) |

`admin delta`, `admin checkpoint` and `admin waste` moved to the top level in 0.29 and were removed
afterwards, together with `admin compress` and `compress-output`; they have no replacement.

The `web` tool and the `basemind web` commands (`scrape`, `crawl`, `map`) were removed, with the
`crawl` cargo feature; they have no replacement. A `[crawl]` table in `basemind.toml` is still
accepted and ignored. Pages already ingested stay searchable under their `web:<host>` scope
(`basemind memory documents <query> --scope web:<host>`) and are no longer refreshed.

The `shell` tool and the `basemind shell` commands (`spawn`, `send`, `capture`, `kill`, `list`,
`broadcast`) were removed, with the `shells` cargo feature; they have no replacement. A `[shells]`
table in `basemind.toml` is still accepted and ignored. Stop a shells daemon an older version left
running before upgrading (`basemind shell kill` each session, or kill the process); this version
still lists it in `basemind comms doctor` but cannot talk to it.

The memory review queue (`audit`, `mine`, `proposals`, `accept`, `reject`) and its `basemind memory`
commands were removed; they have no replacement. Stored notes keep every field, including the verdict and importance
an audit wrote, which nothing updates any more. Archived notes and pending proposals stay on disk in
the repo's `memory.fjall` and are never read. The comms protocol version is now 5: the first
upgraded session replaces a running older daemon, and a client and daemon that still disagree fail
the handshake with `proto_skew`.

The `graph` tool and the `basemind graph` commands (`calls`, `neighbors`, `path`, `subgraph`,
`communities`, `map`, `export`, `display`, `open`) were removed, with the `basemind://repo/map`
resource and the daemon's `/ui` page; they have no replacement. `code_refs` answers the
who-calls-what questions. The daemon's HTTP front-end now serves `/mcp` only and takes the bearer
token in the `Authorization` header only: `?token=` is refused.

The `documents` cargo feature was split into tiers. `documents` is document search without OCR or
named-entity recognition; `documents-ocr` adds Tesseract OCR (raster images and PDFs with no text
layer) and `documents-ner` adds ONNX named-entity recognition (`[documents.ner]` and the
`entity_category` filter). `full` includes all three, so the published binaries are unchanged except
that they no longer contain PaddleOCR, which is the source-only `documents-ocr-paddle` feature. A
source build that used `--features documents` needs
`--features "documents documents-ocr documents-ner"` (or `full`) to keep OCR and NER. Without
`documents-ocr`, raster images are not indexed as documents and a PDF with no text layer is indexed
with no text, with a warning naming the file and the feature; without `documents-ner`,
`[documents.ner] enabled = true` logs a warning and has no effect, and a search with
`entity_category` returns an error. A build with both tiers keeps its cached documents. A build
missing a tier extracts every document again on its first scan, and so does the first scan after
switching to a binary with a different set of tiers.

Archive extraction, LLM-backed (abstractive) summarization and the LLM NER backend were removed, with
HEIC/HEIF, SQLite, WordPerfect, HWP/HWPX and Apple iWork extraction and SVG rasterisation (SVG text
is still read as XML); they have no replacement. These settings are still accepted and ignored, each
with a one-time warning: `[documents] extract_archives = true` (archives are always skipped, and
`BASEMIND_DAEMON_ALLOW_EXTRACT_ARCHIVES` has no effect),
`[documents.summarization] strategy = "abstractive"` (extractive summaries are used),
`[documents.ner] backend = "llm"` (no entities are extracted) and a non-empty `[llm]` table. The
`--llm-*` flags on `basemind scan` and the `BASEMIND_LLM_*` variables are accepted and ignored too.
`max_archive_bytes` and `max_archive_entries` still apply, to the zip containers that Office files
are. A config that set `[llm] model` or `extract_archives = true` has its documents extracted again
once, on the first scan after upgrading; any other config keeps its cached documents.

Also check scripts for these behaviour changes:

- Exit codes are `0` ok, `1` error, `2` usage, `3` writer lock held, `4` daemon unreachable, `130`
  interrupted. `scan` and `rescan` exit `3` (not `0`) when another process holds the lock.
- The timing footer is on stderr; stdout carries only the answer. Human output no longer truncates
  values to 200 characters.
- `agents` and `workspace` `--json` now use the MCP response shapes.
- MCP logging is gone, and document search no longer accepts the `documents.*` / `llm.*` override fields.

## What changes on upgrade

| Change | How it migrates | Cost |
|---|---|---|
| Prose, data and config files (Markdown, JSON, YAML, TOML, XML, CSV, INI, ...) left the code map for the document tier | The next scan, full or incremental, notices a path indexed in the other tier, purges its code-map rows and indexes it as a document | Documents are chunked, and embedded when `[documents] embed` is on |
| Symbol `signature` now ends at the grammar's body field instead of embedding the body | Only files whose entry or blob predates the new extractor epoch are re-extracted, in the normal memory-bounded scan | One parse per affected file, no wipe |
| Release-minor schema bump (for example `0.28.x` to `0.29.x`) | Each view's index is reset on open and every file is re-extracted, overwriting stale blobs in place | Full re-extraction, by design |
| Resident term index, name dictionaries, macOS heap retag | In memory only | None |
| Daemon `IndexRead` forwarding for `code_refs` | Wire protocol only | None |
| Code map is code-only; `find_files` covers documents | Same tier migration as the first row | See above |
| Grep bloom filters | Built on the next scan; until then `code_grep` runs the full sweep | Small, at scan time |

Patch releases keep the persisted format. A change that alters what an unchanged file's blob should
contain, without changing how it is serialized, bumps an internal extractor epoch instead of the
release minor. Every file entry and blob records the epoch it was produced under, so only stale
files are re-extracted, and the scan summary reports them as `refreshed` (and `tier_migrated` for
tier moves).

<Aside type="note">
A minor release bumps the persisted schema and the first `basemind scan` after upgrading rebuilds the
cache from source. No manual step is needed. See [Schema versioning](/reference/configuration/#schema-versioning).
</Aside>

## Automatic cleanup

Content-addressed blobs are shared and never rewritten on their own, so a migration can orphan some
of them. For example, the old `.fm`, `.chunk` and `.rref` blobs of a Markdown file that became a
document kept the same content hash as its live document blob and were pinned forever.

- The sweep is tier-aware: a document blob is live only if some workspace's document table references
  the hash; code-lane blobs are live only if a code-map file entry does.
- It reference-counts against every workspace on the machine, keeps blobs younger than six hours (a
  concurrent scan may be about to reference them), and takes a machine-wide `cache/gc.lock` so two
  sweeps never run at once. `BASEMIND_BLOB_GC_GRACE_SECS` overrides the six hours; `0` reclaims every
  unreferenced blob immediately.
- A scan that migrated a path, refreshed an extraction, or reset a view for a schema bump runs the
  sweep itself and prints `cleanup: reclaimed N orphaned blob(s), B bytes`. In the daemon the same
  condition triggers a sweep a minute later, and the daemon also sweeps hourly.
- `basemind cache gc` performs the same sweep; `--dry-run` only reports. It used to be report-only.
- `cache stats` shows the result as `last_gc`, and its `orphan_blob_count` is tier-aware and drops
  to `0` after the sweep.

A second scan after the upgrade is a no-op: nothing is migrated, refreshed or reclaimed.

<Aside type="caution">
No MCP tool sweeps the cache: a session cannot sweep from inside itself without racing its own
rescans. Use `basemind cache gc` to reclaim space (`--dry-run` only reports).
</Aside>

## Clearing and downgrading

`basemind cache clear --component blobs|views|lance|git-cache|telemetry|all --yes` covers every on-disk
component a migration touches. The term index and name dictionaries are memory only. The sweep lock
is an empty file removed with the cache root, and `git-history.fjall` is removed only by `all`
because the daemon holds it open.

Opening upgraded data with an older binary fails safe. The index extras are ignored; a binary on the
same schema minor re-maps the files it still treats as code (and drops their document entries), and
one on a different minor resets the view and re-extracts, as for any schema change. Going back and
forth costs re-extraction, never correctness, and the next sweep reclaims what is left.

## Plugin binaries

The plugin launcher keeps one `~/.cache/basemind/bin/<version>/` per release, reaps processes of
other versions and removes older version directories on every launch of the current one. That cache
is a few tens of MB per version and is not touched by the migration above.
