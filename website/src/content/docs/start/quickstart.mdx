After installing, index a repository and ask it questions. Most answers come back
in **about a millisecond** — the index is held by a background daemon, so a query never re-reads your project.

<Aside type="tip">
New to a repo? Run `basemind init` (or `/bm-init`) first — see
[Get started](/start/installation/#get-started) — to scaffold `basemind.toml`
and wire agent-instructions rules before you scan.
</Aside>

<Steps>

1. **Index the repository**

   From the repository root:

   <Code code={`basemind scan`} lang="bash" />

   This walks the tree, parses with tree-sitter, and writes a content-addressed
   blob store + inverted index in the global cache (`~/.local/share/basemind/` on Linux, `~/Library/Application Support/basemind/` on macOS). Takes a few seconds for small
   repos, around 18 seconds for an 81k-file TypeScript monorepo.

2. **Find where a symbol is defined**

   <Code code={`basemind code symbols "parse_query"`} lang="bash" />

   Output, one definition a line as `<path>:<line>: <signature>`, best match first:

   <Code code={`results:
  src/parser.rs:142: pub fn parse_query(input: &str) -> Result<Query>
  src/cli/args.rs:89: fn parse_query(raw: &str) -> Query`} lang="text" />

   Now you know exactly where to read — no grep noise, no manual parsing.

3. **See what calls a function**

   <Code code={`basemind code refs "process_file"`} lang="bash" />

   Output:

   <Code code={`total: 3

hits (3 items):
  src/scanner.rs:142
  src/scanner.rs:201
  src/extract.rs:57`} lang="text" />

   Every place it's called, by file and line. For the full hits, with the column of calls that
   share a line and how each call was bound (`resolution`, per hit or once as the page's
   `resolution_default`), ask for JSON ([MCP tools](/reference/mcp-tools/)):

   <Code code={`basemind code refs "process_file" --json`} lang="bash" />

4. **Find who last touched a line**

   <Code code={`basemind git blame src/main.rs`} lang="bash" />

   Or drill down to a single symbol:

   <Code code={`basemind git blame-symbol src/main.rs "process_file"`} lang="bash" />

   Lists each run of lines with the commit that last changed it, then each of those commits'
   author, time and summary.

5. **Keep the index fresh**

   As you edit, update the index with:

   <Code code={`basemind watch`} lang="bash" />

   This runs in the foreground and re-indexes on file changes. Or use `basemind
   serve` if you're querying via the MCP server or plugin.

</Steps>

## What to expect

- **Index build**: Seconds for small repos; the largest test case (81k TypeScript
  files) scans in around 18 seconds. Re-scans are much faster — only changed
  files are re-indexed.

- **Query latency**: about a millisecond for an outline and 1–5 ms for symbol, reference
  and caller lookups on a 74k-file monorepo (in-process, p50; smaller repos are
  faster). Git history lookups in **tens of microseconds**.
  See [Performance](/reference/performance/).

- **Outline before you read**: Use `code_outline` to see a file's
  structure (symbols, signatures, line numbers, imports) without opening it.

  <Code code={`basemind code outline src/parser.rs`} lang="bash" />

  Output shows every symbol and its line number, so you know exactly what to read.

## Using the plugin or MCP server

If you're using the plugin or MCP server instead of the CLI, you're already
indexed once you run `/bm-scan` or call `index_rescan`. From
there, use the tools in the chat:

- **Find a definition**: Call `code_symbols` with a `name`.
- **Find references**: Call `code_refs` with a `name`.
- **Browse before reading**: Call `code_outline` with a `path`.
- **Check git history**: Call `git_blame` with a `path` and `symbol`, or `git_log`
  (no arguments for recent commits, `path` for one file).

All the same queries, just over the MCP surface instead of the CLI.

<Aside>
After re-indexing, both the CLI (`basemind code ...` / `basemind git ...`) and
the MCP tools have the fresh index. No server restart needed — use `index_rescan`
(or `basemind rescan`) to update in-process.
</Aside>
